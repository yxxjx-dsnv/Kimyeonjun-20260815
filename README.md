# 쇼포트 명품 에이전트 (프로토타입)

**정확한 상품명을 몰라도, 기억나는 특징의 서술만으로 상품을 찾아주는 대화형 탐색 에이전트.**
찾아준 상품이 새상품·중고·판매처별 가격 대비 얼마나 유리한지까지 계산해 제시합니다.
쇼포트의 신규 카테고리 에이전트를 제안하는 형태로, **실제 쇼포트 앱 화면을 기준으로 UI를 재현**해 구현한 레브잇 PMF 직무 과제 프로토타입입니다.

🔗 **배포 링크: https://luxury-agent-demo.vercel.app**

```
"샤넬백인데 검정색 캐비어 가죽에 금장 로고 있는 거"
                       ↓
  AI가 후보 3개 + 왜 이게 맞는지 근거
+ 새상품 최저가 613,000원 → 이 중고 매물 169,000원 = 지금 사면 절약 444,000원 (72%)
```

## 로컬 실행

```bash
npm install
echo "OPENAI_API_KEY=sk-..." > .env.local

npm run crawl      # (선택) 상품 데이터 재수집 → data/products.json
vercel dev         # http://localhost:3000 — 프론트 + /api 함께 실행
```

`vercel dev` 없이 프론트만 볼 때는 `npm run dev` (5173 → 3000으로 `/api` 프록시).

## 구조

```
crawler/crawl.js   5개 쇼핑몰 크롤러 — 번개장터(중고 명품)·다나와(가격비교)·29CM·무신사(패션)·컬리(뷰티/생활)
data/products.json 크롤링 결과 756건 (새상품 461 / 중고 295) — 명품 475·패션 128·뷰티 126·생활 27
```

# 구현에 대한 설명

## 1. 어떤 문제를 풀었나 — 과제 1과의 연결

과제 1에서 정의한 문제는 하나의 구매 여정에 이어진 두 가지입니다.

1. **탐색**: 명품의 상품명은 외국어 고유명사 조합(*디올 새들 로터스 월렛 오블리크*)인데, 사람 머릿속에 상품은 **이름이 아니라 특징의 묘사**로 저장된다. 키워드 검색창은 이 묘사를 받아주지 못한다.
2. **결정**: 고가 상품이라 "이 가격에 사도 되나"라는 확신이 없으면 결제를 미루고, 미뤄진 구매 의도는 대부분 돌아오지 않는다.

이 프로토타입은 쇼포트가 지향하는 **메타 커머스** 관점을 그대로 따릅니다. 특정 판매처의 이해관계에 묶이지 않고 5개 쇼핑몰(번개장터·다나와·29CM·무신사·컬리)을 함께 수집해, 고객에게 지금 가장 합리적인 선택지가 무엇인지 — 중고가 얼마나 절약되는지, 어느 판매처가 더 싼지, 오히려 새상품이 더 싼 건 아닌지 — 를 그대로 보여줍니다. 명품(과제 1의 비치헤드)에서 시작해 쇼포트의 실제 커버리지인 패션·뷰티·생활 카테고리까지 같은 구조로 확장했습니다.

UI는 실제 쇼포트 앱을 설치해 화면 단위로 확인하고 그 문법(홈 히어로 입력 카드, 2×2 질문 선택지, 말풍선 없는 에이전트 발화, 질문 카드와 선택지, 블랙 CTA "최저가 구매하기")을 재현했습니다 — 별도 서비스가 아니라 **쇼포트 인앱 신규 기능 제안**으로 바로 읽히게 하기 위해서입니다. 화면과 README 모두에 실제 쇼포트 서비스가 아닌 과제 프로토타입임을 고지했습니다.

## 2. 강조하고 싶은 설계 판단

**(1) 미니 카탈로그 파이프라인 — 흩어진 상품 정보를 비교 가능한 구조로.**
5개 소스의 상품명 형식은 전부 다릅니다(판매자 서술형 / 품번 포함 정식명 / [브랜드] 접두). 크롤러가 **속성을 추출·구조화**하고(브랜드+축약형 별칭, 종류 26종, 명품 모델 라인 60여 개, 새상품/중고, 검수 가능, 리뷰 평점), `브랜드|종류|모델` 그룹으로 묶어 **소스가 달라도 같은 상품끼리** 비교되게 했습니다. 서로 다른 판매처가 한 그룹에 묶인 비교 그룹 57개 — "쿠팡·11번가식 판매처별 가격 비교"가 실데이터로 동작합니다.

**(2) '절약 계산서' — 가격 확신을 %가 아니라 원화로.**
새상품 최저가(다나와 집계) → 이 중고 매물 → **"지금 사면 절약 444,000원 (72%)"**. 구매를 미루게 하는 질문("이 가격에 사도 되나")에 계산서 형태로 답합니다. 반대 방향도 숨기지 않습니다 — 중고가 새상품보다 비싸면 **"새상품이 더 저렴해요 → 새상품 보기"** 링크를 보여줍니다. 판매처 이해관계가 없기에 가능한 정직함이고, 이 정직함이 곧 재방문 이유라고 판단했습니다.

**(3) 대화 정책 — 흔한 실패 패턴의 정반대, 프롬프트가 아니라 코드로.**
대화형 쇼핑 에이전트가 실사용에서 가장 많이 비판받는 패턴은 "질문만 계속하고 결과를 안 준다", "대답해도 무시한다"입니다. 정책을 서버 코드로 강제했습니다:

- **질문은 대화 전체에서 최대 1번.** 후보를 함께 제시한 채로만 물을 수 있고, 2턴째부터는 코드가 되묻기를 차단.
- **매 턴 후보 필수.** AI가 빈손이면 키워드 매칭(브랜드·종류·색상 점수화)이 백스톱으로 후보를 채움.
- **브랜드 가드.** 언급된 브랜드 외 상품은 코드 레벨에서 차단 (실사용 버그에서 도입 — 아래 결함 ④).
- **절약 질문 보장.** "얼마나 아껴?" 류 질문이면 절약 계산서가 붙는 매물을 서버가 반드시 포함 (아래 결함 ⑥).
- 되묻기 선택지는 **탭 가능한 칩** — 40-50대 사용자의 타이핑 부담을 줄입니다.

**(4) 1단계 검색(retrieval) — 요청당 24k → 2~7k 토큰.**
756건 전체를 매 요청 프롬프트에 넣자 OpenAI 분당 토큰 한도(429)에 걸리는 것을 E2E 테스트에서 실측했습니다. 대화에서 감지한 브랜드·카테고리로 카탈로그를 좁혀 보내고, 단서가 없으면 그룹별 대표 2건으로 요약해 보내는 검색 단계를 서버에 구현했습니다. 응답 속도가 3.5초 → **1.5~2초**로 줄었고, 상품 수가 늘어도 버티는 구조가 됐습니다.

**(5) 숫자의 정직함 — 근거가 약하면 숫자를 만들지 않는다.**
- AI는 가격을 언급할 수 없습니다(환각 위험). 가격은 전부 서버가 크롤링 데이터로 계산합니다.
- AI가 지어낸 상품 id는 카탈로그 조인에서 걸러져 화면에 못 올라옵니다.
- 비교군 3건 미만이면 시세를 만들지 않고, 최고/최저 편차 4배 초과 그룹은 "시세 대비 N%" 대신 "12건 중 1번째로 저렴"이라는 반박 불가능한 사실만 보여줍니다.

**(6) 검증을 코드로 남겼습니다.**
순수 로직 self-check(`node api/_intel.js`, `node api/chat.js`), SSR 렌더 검증 22항목, OpenAI 실호출 E2E 10개 시나리오(과거 실패 사례들이 회귀 테스트로 고정), Playwright 실브라우저 플로우 17단계(홈→대화→카드→절약 계산서→가격 비교→찜→둘러보기→상세 시트). 발표자료의 앱 스크린샷도 이 브라우저 테스트가 촬영한 것입니다.

## 3. 겪은 어려움과 해결

**① 필웨이 크롤링 — 200 OK가 성공이 아니었다**

처음 타깃이던 중고명품 마켓 필웨이는 봇 차단 없이 200을 주고 상품 100건이 서버렌더링되어 있어 파싱까지 마쳤습니다. 그런데 "디올 지갑"과 "구찌 가방"의 결과가 완전히 동일했고, 서버렌더링된 100건은 **전부 광고 슬롯**(남성 티셔츠 포함)이었습니다.

> **배운 것**: 응답 코드와 그럴듯한 HTML은 크롤링 성공의 근거가 못 됩니다. **입력(검색어)을 바꿨을 때 출력이 실제로 달라지는지**까지 확인해야 검증이 끝납니다.

**② 크롤링 소스 확장 — 17곳을 실측해서 5곳이 남았다**

위 교훈을 기준 삼아, 파서를 쓰기 전에 curl로 먼저 실측했습니다.

| 결과 | 소스 |
|---|---|
| **채택 (5)** | **번개장터**(중고 매물·공개 검색 API) · **다나와**(새상품 판매처별 최저가·SSR) · **29CM**(패션·검색 API) · **무신사**(패션·`caller=SEARCH` 파라미터 필요) · **컬리**(뷰티/생활·검색 API) |
| 광고 슬롯 | 필웨이 (200이지만 검색어 무반응) |
| 403 차단 | 네이버쇼핑, eBay, SSG, G마켓, 올리브영 |
| SPA/오류 | 트렌비, 발란, 머스트잇, KREAM, 에누리, W컨셉, 헬로마켓, 중고나라, 11번가 |

다나와는 품번 포함 정식 모델명과 판매처별 최저가를, 번개장터는 서술형 제목의 중고 매물을 줍니다. 이 조합으로 "중고가 새상품 대비 얼마나 싼가"(절약 계산 가능한 중고 매물 147건)가 실데이터로 성립하고, 29CM·무신사·컬리가 패션·뷰티·생활을 채워 **명품 밖 카테고리에서도 같은 구조가 동작함**을 증명했습니다.

**③~⑥ 실사용·자동화 테스트에서 잡은 결함 4건**

3. **"샤넬 가방"에 7만원짜리 빈 상자가 매칭.** 제목이 `*클래식백* 샤넬 자석 박스 … 쇼핑백`이라 텍스트상 완벽한 후보였습니다. 부속품 필터를 넣되 `박스`를 통으로 막으면 "가방 + 박스"(진짜 가방)가, `참`을 막으면 `참월렛`(480만 원)이 죽어서 **합성어 단위로만** 차단했습니다.
4. **"샤넬 검정 누빔"에 생로랑 마틀라세가 노출.** LLM이 속성 유사도만 보고 브랜드를 무시한 실사용 스크린샷 사례. 언급된 브랜드 외 상품을 **서버가 걸러내는 브랜드 가드**를 추가하고 회귀 테스트로 고정했습니다.
5. **756건 전체 프롬프트가 분당 토큰 한도(429)에 걸림.** E2E가 잡아낸 확장성 문제 — 1단계 검색 도입으로 해결 (위 설계 판단 4).
6. **"얼마나 아껴?" 질문에 절약 계산서 없는 매물이 나옴.** 브라우저 E2E가 잡아냈고, AI가 계산서 가능 여부를 알 수 없던 것이 원인. 카탈로그에 `절약비교가능` 컬럼을 추가하고, 그래도 놓치면 **서버가 절약률 최대 매물을 직접 채워 넣도록** 보장했습니다. 핵심 가치가 걸린 경로는 모델 판단에 맡기지 않습니다.

*(15만원 복조리백에 "시세 92% 저렴" 배지가 붙던 시세 왜곡 결함과 그 해결 — 편차 4배 초과 시 % 포기 — 은 위 설계 판단 5에 반영되어 있습니다.)*

## 4. 아쉬운 점 · 개선 여지

**지금 구조의 한계**

- **매칭이 텍스트 기반이라 상품명에 없는 정보는 못 찾습니다.** "금색 D 장식", "물결 모양 뚜껑" 같은 묘사는 판매자가 안 쓰면 반영되지 않습니다. → 상품 이미지를 Vision 모델로 캡셔닝해 색·형태·장식 속성을 카탈로그에 미리 **생성**해 두는 것이 1순위 개선입니다.
- **1단계 검색이 규칙 기반입니다.** 브랜드·카테고리 감지는 정확하지만 "결혼식 하객룩" 같은 상황형 질의는 못 좁힙니다. → 임베딩 검색으로 교체하면 지금 구조(검색→LLM) 그대로 업그레이드됩니다.
- **동일 상품 판별이 거칩니다.** 소스 간 같은 모델 매칭이 키워드 규칙이라 신규 라인·비표준 표기를 놓칩니다. → 품번 정규화 + 임베딩 클러스터링.
- **시세가 크롤링 시점 스냅샷입니다.** → 주기 재수집(cron) + 가격 추이. "3개월 내 최저가" 신호가 구매 확신에는 더 강력합니다.
- **가격 이상치 경고가 없습니다.** 시세보다 과하게 싼 중고 매물은 오히려 위험 신호인데, 시세 분포를 이미 갖고 있어 바로 붙일 수 있는 다음 기능입니다.

**검증하고 싶은 것 (과제 1의 실험 설계와 연결)**

- H1(서술형 검색이 발견율을 높이는가): 3턴 내 발견율, 대화 시작→카드 클릭률.
